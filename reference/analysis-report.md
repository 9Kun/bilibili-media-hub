# B站视频分析报告规范

仅在 `--analyze` 已生成分析清单后读取本文件。Python 负责准备材料；当前宿主 Agent 负责理解文本、生成报告、写入 Markdown 并在对话中展示。

## 输入处理

1. 读取清单中的 `video`、`pages`、`summary` 和 `report_path`。
2. 只读取 `status=ready` 的 `source_path`：
   - `source_format=srt`：保留每条字幕的开始时间。
   - `source_format=timestamped_text`：保留每句的 `[MM:SS]`。
3. 按清单的 `source_type` 注明每P素材来源：`cc` 写“人工/UP主CC字幕”，`ai_subtitle` 写“B站AI智能字幕”，`asr` 写“本地FunASR”。AI智能字幕和本地ASR可能存在同音字、断句及专有名词错误，只能结合标题、简介和上下文适度纠正，不得补写素材中没有的事实。
4. 单P文本超过 20,000 字符时，按已有时间戳边界切成不超过 12,000 字符的连续片段；先分别总结，再合并最终报告。

## 报告结构

报告使用中文 Markdown，并按以下顺序输出：

```markdown
# B站视频分析报告

## 视频信息
标题、UP主、BV号、分析分P、素材来源与失败分P

## AI标题
不超过30字

## 一句话结论
不超过60字

## 内容摘要
200–300字

## 详细总结
完整说明主题、论证过程、结论及重要限制

## 核心要点
3–8条

## 章节时间线
| 分P | 时间 | 章节 | 内容 |
| --- | --- | --- | --- |
```

单P直接生成上述结构。多P先生成全视频总览，再增加“分P分析”章节；每个成功分P分别包含简要摘要、核心要点和章节时间线。失败分P只列出清单中的真实错误，不推测其内容。

## 章节规则

- 按主题或论述阶段的真实转折划分，不按固定分钟数机械切割。
- 短视频允许 1–3 章，普通或长视频通常 3–12 章；内容本身不足时不要凑数。
- 时间必须逐字引用素材已有的开始时间；SRT 统一显示为 `HH:MM:SS`，文字稿保留 `[MM:SS]` 的等价时间。
- 多P时间线标记 `P序号 + 分P标题 + 分P内时间`。各P从自身时间轴开始，不构造跨P累计时间。
- 章节描述应概括该时间点开始的内容，不复制长段字幕。

## 输出要求

将最终 Markdown 写入清单中的绝对 `report_path`，使用 UTF-8。随后在对话中返回同一份完整报告并附可点击文件链接。不得加入画面、PPT、图表或视觉判断，因为本流程没有读取视频画面。
